# Conversation Workflow

## Purpose

Use conversation to develop the user's thinking, not to force every input into a card.

## One-turn pattern

1. Briefly reflect the user's current position.
2. Identify the most productive uncertainty, assumption, boundary, or consequence.
3. Ask one main question.
4. Offer natural-language exits: continue, update this card, create a new card, find links, stop here, or discard.

## Handling replies

- **Continue:** ask the next question only if it adds a genuinely new angle.
- **Update:** revise the candidate while preserving the prior thought in the conversation log.
- **New card:** branch only if the reply contains an independently reusable claim.
- **Find links:** compare claims and contexts across the vault; propose relationships with reasons.
- **Stop here:** close the conversation and preserve the current candidate or notes.
- **Discard:** close the conversation without promoting the candidate.
- **Approve:** promote only when approval is explicit and the configured permanent destination is known.

## Avoid

- repeating the source as a summary and calling it the user's view;
- asking several unrelated questions at once;
- creating cards for every paragraph of a reading export;
- linking cards solely because they share a keyword;
- continuing a dialogue after the user has chosen to stop.
